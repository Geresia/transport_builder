# 통합 건설 공정표 엔진 구현 보고서

- 기준일: 2026-09-27
- 구현 단계: A6-1 완료
- 기준 시간: 1개월 = 시뮬레이션 30일
- 담당 경계: 지도는 공사구역·교차·충돌 같은 공간 사실을 제공하고, 경영 엔진은 작업 순서·진척·지연·개통 관문을 계산한다.

## 1. 구현 결과

기존에 따로 진행되던 노선 본체, 역, 차량기지와 차량 제작을 하나의 작업 그래프로 묶었다.

```text
설계·인허가
  ├─ 구간별 토목 공사 ─┐
  ├─ 역별 공사 ───────┤
  ├─ 차량기지 건설 ───┼─ 궤도·전력·신호 ─ 종합시험·안전검사 ─ 개통 준비
  └─ 차량 설계·제작 ──┘
```

토목 구간은 노선 견적의 동시 공사 전면 수에 따라 나뉜다. 같은 전면에 배정된 구간은 순차 시공하고, 서로 다른 전면은 병행할 수 있다. 모든 의존관계는 순환이 없는지 생성 시 검증한다.

## 2. 기준 공정과 예측 공정

공정표 생성 시점에 기준 공정을 고정한다.

- `baselineStartMonth`, `baselineFinishMonth`: 최초 계약 기준
- `forecastStartMonth`, `forecastFinishMonth`: 현재 상태와 지연을 반영한 예측
- `actualStartMonth`, `actualFinishMonth`: 실제 진행이 관측된 월
- `delayMonths`: 기준 대비 현재 지연
- `critical`: 현재 예상 개통일을 결정하는 작업 연결

기준 공정은 후속 지연 때문에 다시 쓰지 않는다. 따라서 플레이어는 원래 개통 목표와 현재 예상 개통일을 비교할 수 있다.

## 3. 선행조건과 개통 관문

하위 시스템이 거친 상태값으로 완료를 반환하더라도 선행 작업이 끝나지 않았으면 해당 작업은 `blocked`가 된다.

- 토목·역 공사 완료 전 시스템 통합 불가
- 시스템·역·차량기지·차량 제작 완료 전 종합시험 불가
- 종합시험 완료 전 개통 준비 완료 불가
- 공정표가 존재하면 `ScenarioRuntime.open()`도 공정표의 `ready`를 확인

따라서 노선 본체만 완공됐거나 차량만 준비된 상태로 개통할 수 없다.

## 4. 지연 전파

`delayIntegratedTask()`로 작업에 지연 개월과 원인을 기록할 수 있다.

- 지연은 해당 작업의 예상 완료월을 늦춘다.
- 모든 후속 작업과 예상 개통월에 자동 전파된다.
- 기준 공정은 보존된다.
- 원본 공사 시스템이 먼저 완료를 반환해도 지연 해소월 전에는 작업을 완료 처리하지 않는다.
- 지연 사건은 ID, 발생 시각, 작업 ID, 개월, 사유, 출처와 함께 저장된다.

이 API는 다음 단계의 물가 상승·자재 부족·사고·민원·인허가 사건이 공정에 영향을 주는 공통 진입점이다.

## 5. 시나리오와 저장 연결

시나리오에서 차량기지 계약과 차량 발주를 완료하면 공정표가 자동 생성된다. 매월 다음 순서로 갱신된다.

1. 노선 공사 진행
2. 역 패키지 상태 동기화
3. 차량 제작 진행
4. 차량기지 공사 진행
5. 통합 공정표 재계산

공정표·작업 상태·기준일·지연 사건은 `ManagementGame` 저장에 포함된다. 이전 저장처럼 공정표가 없는 상태도 빈 배열로 복원한다. `ScenarioRuntime.report()`는 지도 표시 모듈이 읽을 수 있도록 공정표를 함께 반환한다.

## 7. 현재 한계

- 구간별 실제 진척은 아직 노선 본공사의 토목 진척을 공통 원천으로 읽는다. Claude의 공구 계약이 연결되면 공구별 독립 진척으로 교체한다.
- 역 패키지는 실제 상세 패키지가 없으면 노선 토목 진척을 사용하는 대체 작업으로 표시한다.
- 지연 원인은 수동 API로 기록할 수 있지만 물가·자재·사고 사건 생성기는 아직 없다.
- 공정 만회, 야간작업, 추가 공사 전면, 시공사 교체는 다음 단계다.
- 월별 간트 UI는 아직 없으며 엔진 조회값과 지도용 보고서까지만 제공한다.
