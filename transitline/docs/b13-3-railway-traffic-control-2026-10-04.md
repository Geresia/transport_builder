# B13-3 실제 열차 폐색·정시율 연결

## 결과

시간표에서 승인된 열차가 실제 시뮬레이션 선로에서 서로 겹치지 않도록 물리 구간 점유를 검사한다. 신호 대기와 놓친 운행, 실제 도착 지연은 누적 운행 사실로 저장되고 일반 서비스의 일일 정산 정시율과 공공서비스 KPI에 반영된다.

## 폐색 규칙

- 운행선의 연속 역 쌍을 실제 `trackSegmentId`로 해석한다.
- 복선은 물리 진행 방향별로 별도 폐색 자원을 사용한다.
- 단선은 양방향이 하나의 폐색 자원을 공유한다.
- 진입하려는 폐색에 다른 열차가 있으면 역에서 대기하고 `signalDelaySeconds`를 누적한다.
- 같은 순간 양쪽에서 단선에 진입하면 결정론적인 열차 처리 순서상 먼저 진입한 열차만 허용된다.
- 선로 상태가 `available`이 아니면 진입을 차단한다.
- 경영 서비스·직통 서비스·소유 선로의 실제 구간 연결이 없거나 같은 역 쌍에 둘 이상이면 진행으로 간주하지 않고 `unmapped-section`/`ambiguous-section` 정지 신호를 낸다. 물리 자산 계약이 생기기 전 만들어진 직통 바인딩은 생성 시 `legacy-unmapped` 호환 모드를 명시적으로 붙이고 종전 방식으로 움직인다. `null=진행`으로 암묵 처리하지 않는다.
- 단·복선 사실이 없으면 안전 쪽인 단선 공유로 처리한다. B13-2 시간표가 활성화되면 심사에 사용한 명시적 단·복선 사실을 운행 제어에도 그대로 적용한다.

현재 폐색은 `trackSegment` 하나를 블록 하나로 보는 보수적 모델이다. Claude의 B13-M5 지도 계약에서 실제 폐색 경계가 오면 한 물리 구간 안의 복수 블록으로 확장한다.

## 운행 실적

운행선별 누적 사실은 `stats.railwayTrafficByLine`과 `report().railwayTraffic`에 나타난다.

- `dispatchedTrains`
- `completedTrains`
- `scheduledDispatchedTrains` / `unscheduledDispatchedTrains`
- `scheduledCompletedTrains`
- `onTimeTrains` — 예정 종착시각 5분 이내
- `missedDepartures`
- `departureDelaySeconds`
- `signalDelaySeconds`
- `arrivalDelaySeconds`
- `completionOnTimeRatio` — 완료된 시간표 열차 중 5분 이내 도착 비율
- `serviceDeliveryRatio` — 예정 출발 및 놓친 출발 전체 중 정시 완주 비율

보고서는 복사본이며 읽어도 운행 상태를 바꾸지 않는다. 통합 저장은 기존 운행 상태 스냅샷 규칙으로 이 누적값과 열차의 예정 복편·종착시각, 신호 대기 상태를 함께 보존한다.

## 경영 정산 연결

운행 실적은 실제 완료 시각이 아니라 예정 출발일 기준 일별 버킷에도 기록한다. 자정을 넘어 완주해도 원래 운행일에 귀속된다. 일반 서비스 일일 정산은 아직 완주하지 못한 편성도 포함해 `시간표 출발 + 놓친 출발` 전체를 의무 운행으로 보고 `serviceDeliveryRatio`를 계산한다. 따라서 전 열차가 폐색에 갇힌 날이 실적 없음으로 빠져 높은 기본 정시율을 받지 못한다. 기존 차량 고장·시설 상태·공사 점유·선로 사용·인력 정책으로 만든 모델 정시율과 실제 서비스 이행률 중 낮은 값을 KPI 정시율로 사용한다.

시간표 없이 주파수로 운행한 열차는 별도 `unscheduled*` 항목으로 세며, 시간표 정시율의 분자나 분모에 넣지 않는다.

따라서 신호 대기 자체가 곧바로 현금을 차감하지는 않지만, 실제 지연·운행 누락으로 정시율이 떨어지면 기존 계약의 보너스·감액 구조를 통해 영업 성과에 반영된다.
