# B12~B20 교통회사 경영 시뮬레이션 로드맵

## 방향

플레이어는 도시를 마음대로 그리는 시장이 아니라, 현실의 물리·허가·계약·공사·운영 제약 안에서 버스와 철도를 설계하고 경쟁하는 교통회사 사장이다. 지도는 공간 사실을 제공하고, 경영 엔진이 돈·시간·위험·계약·판정을 담당한다. 도로망은 주어진 도시 기반으로 유지한다.

## 현재 위치

- B0~B11: 기본 건설, 역·차량기지, 차량, 시공사, 사건, 운영경제, 경쟁·선로사용까지 구현됨
- B12-1~B12-5: 직통 경로, 기술호환, 차량개조, 연락운임, 실제 정산, 지도 운행 연결 구현됨
- B12-6: 연락선·분기기 별도 건설사업 구현됨 (`18131a2`)
- B12-7: 영업선 점유전략과 대체수송·영업손실 구현 중
- B12 지도 현장 계약: Claude 별도 worktree에서 진행

## 단계

### B12 — 직통운행 전체 사이클

외부망 사양 조사, 물리 접속, 차량 기술호환, 선로사용계약, 연락운임, 차량개조, 연락선 공사, 영업선 점유, 실제 운행과 정산을 하나의 사이클로 닫는다.

완료 관문:

- 떨어진 두 노선은 연락선 완공 전 운행할 수 없음
- 변경된 노선 개정에는 이전 접속승인이 재사용되지 않음
- 외부 소유자 허가·선로사용·운임협정·차량호환이 모두 유효해야 개통
- 공사 중 기존 서비스 손실과 대체수송비가 실제 경영결과에 반영
- 지도 후보 선택부터 UI에서 전체 흐름을 실행 가능

### B13 — 시간표·운행경로·선로용량

시간대별 열차슬롯, 단선·복선, 대피·완급결합, 회차용량, 분기기 충돌, 역 정차시간과 최소 운전시격을 구현한다. 선로사용계약과 직통열차도 같은 슬롯을 경쟁한다.

완료 관문:

- 물리적으로 가능한 노선도 시간표가 충돌하면 개통 불가
- 배차를 늘리면 수요는 좋아지지만 차량·승무원·전력·슬롯 비용이 증가
- 공사 점유시간에는 해당 슬롯이 실제로 사라짐
- 같은 입력·시드에서 시간표와 지연 전파가 재현됨

### B14 — 관제·장애·회복운전

차량고장, 신호장애, 인명사고, 기상, 공사장 사고, 혼잡으로 인한 지연을 시간축에 발생시키고 회차·구간운휴·대체수송·타사 우회·복구 우선순위를 선택하게 한다.

완료 관문:

- 장애가 열차·승객·KPI·보상·평판·정비비에 중복 없이 연결
- 플레이어 대응에 따라 복구시간과 손실이 달라짐
- 직통 상대 회사의 장애와 책임분담도 계약대로 정산
- 저장·복원 후 동일 장애 상태와 관제명령 유지

### B15 — 수요·혼잡·운임 심화

시간대·OD·환승·혼잡회피·정기권·IC·거리/구간운임·회사별 배분을 실제 승객 선택과 연결한다. 역 출입구와 환승통로의 용량도 수요에 영향을 준다.

완료 관문:

- 중간 승하차와 환승 승객의 운임을 실제 이용 구간별로 배분
- 혼잡·대기·환승거리·신뢰도가 수단·경로선택을 바꿈
- 증편·장대화·출입구 추가·환승개량의 투자효과를 비교 가능
- 수입 합계가 승객별 과금 및 회사별 배분과 1엔 단위로 일치

### B16 — 인력·노무·조직

기관사·차장·역무·정비·관제·공사관리 인력을 채용·교육·교대표로 관리한다. 일본과 한국의 자격·근로·외주·노사관계 차이를 국가 프로필로 분리한다.

완료 관문:

- 차량과 선로가 있어도 자격 인력이 없으면 운행 불가
- 무리한 교대표는 비용을 줄이지만 피로·사고·이직 위험을 높임
- 신규 차량·신호·직통운전에는 추가 교육기간과 비용 필요
- 파업·인력부족·외주화가 서비스와 평판에 일관되게 반영

### B17 — 자산수명·중정비·갱신

선로, 분기기, 전력, 신호, 역, 터널, 교량, 차량, 차량기지 설비에 수명과 상태를 부여하고 검사·보수·중정비·갱신공사를 계획한다.

완료 관문:

- 예방정비를 미루면 현금은 남지만 고장·속도제한·사고위험이 상승
- 갱신공사는 B13 슬롯과 B14 관제를 실제로 사용
- 자산가치·감가·충당금·부채와 현금흐름이 회계에 연결
- 30년 운영에서 자산 상태가 무한히 새것으로 남지 않음

### B18 — 회사전략·경쟁·사업포트폴리오

경쟁사 AI가 입찰, 신규노선, 증편, 운임, 직통제휴, 차량·정비 조달을 플레이어와 같은 규칙으로 수행한다. O&M, 건설, 선로임대, 부동산 연계 등 사업별 손익을 분리한다.

완료 관문:

- 경쟁사에 무한자금·즉시공사 특혜가 없음
- 시장 수요와 시공사·제작사 생산능력을 서로 경쟁
- 제휴·공동투자·인수·철수 결정이 재무제표와 네트워크에 반영
- 회사별 전략 차이가 동일 시나리오에서 관찰 가능

### B19 — 도시성장·역세권·정책 피드백

플레이어가 건물을 직접 짓는 게임으로 바꾸지 않고, 접근성·혼잡·운임·정책에 따라 인구·고용·지가·개발계획과 교통수요가 장기적으로 변하도록 한다. 기존 도로는 도시 조건으로 유지한다.

완료 관문:

- 역과 버스망이 좋아지면 수요·지가·개발이 시간차를 두고 변화
- 무계획 노선은 단기 수요가 낮아 재무 압박을 받음
- 개발이익 환수·부담금·공공지원이 국가 프로필과 계약에 연결
- 지도 데이터 결측은 성장 0이나 무제한 개발로 바뀌지 않음

### B20 — 30년 캠페인·AI·통합 완성

기존망 유지형과 초기화형, 자유예산과 제한예산, 난이도 상·중·하를 실제 캠페인으로 묶는다. 튜토리얼, 목표, 파산·구제·승계, 장기 성과평가, 저장 마이그레이션, 성능을 완성한다.

완료 관문:

- 한국·일본 대표 시나리오를 각각 30년 자동·수동 플레이 가능
- 건설·차량·기지·시간표·운영·정비·경쟁·도시피드백이 한 저장본에서 지속
- 월별 원장·현금·약정·자산·부채가 장기 실행 후에도 일치
- 모든 AI와 플레이어가 같은 핵심 규칙을 사용
- 구버전 저장 마이그레이션, 결정론 재생, 성능 기준, 브라우저 E2E 통과

## 실행 순서

각 B 단계는 다음 순서로 나눈다.

1. 순수 계약·계산 모듈
2. `ManagementGame` 트랜잭션·저장·복원
3. `ScenarioRuntime` 보고와 지도 계약 연결
4. 실제 UI 조작
5. 단위·회귀·브라우저 E2E
6. 문서·커밋·push

지도·공간 사실 계약은 Claude가 별도 worktree에서 작성할 수 있고, Codex가 경영 엔진과 본선 통합을 소유한다. 단계 번호는 문서 작성 완료가 아니라 위 완료 관문을 테스트로 증명했을 때만 완료로 바꾼다.
