# A6 공사 구역·공정 지도와 경영 엔진 연동 보고서

- 기준일: 2026-09-28
- 범위: `ConstructionSiteGeometry`를 통합 공정표와 시나리오 런타임에 연결
- 책임 경계: 지도는 공간 사실과 후보지를 제공하고, 경영 엔진은 상태·진척·지연·사건을 계산한다.

## 1. 구현 결과

클루드가 만든 공구 형상을 별도의 두 번째 공정으로 진행시키지 않고, 기존 통합 공정표의 작업에 연결했다. 따라서 같은 공사에 시간과 비용이 두 번 반영되지 않는다.

| 지도 공구 종류 | 경영 엔진 작업 |
|---|---|
| `tunnel` | 연결된 구간의 토목 작업 |
| `cutCover` | 연결된 구간의 토목 작업 |
| `viaduct` | 연결된 구간의 토목 작업 |
| `systems` | 궤도·전력·신호 통합 작업 |
| `station` | 연결된 역의 토목 작업 |
| `depot` | `connectedDepotSiteId`와 일치하는 차량기지 작업 |

공구의 폴리곤, 횡단점, 후보지, 결측값과 `unknownReasons`는 원본 계약 그대로 보관한다. `null`을 0으로 바꾸거나 지도 자료만으로 비용·공기·소유권을 추정하지 않는다.

## 2. 런타임 보고서 계약

`ScenarioRuntime.report()`는 지도 표시용으로 다음 값을 반환한다.

```js
{
  constructionPackages: {
    [constructionSiteId]: {
      status,
      progress,
      delayMonths,
      critical
    }
  },
  constructionMarkers: [
    {
      constructionSiteId,
      kind, // incident | complaint | material-shortage
      location,
      message
    }
  ]
}
```

공구 상태는 통합 공정의 작업 상태에서 파생한다. 공구가 여러 구간 작업에 연결되면 작업 기간을 가중치로 사용해 진척률을 합산하고, 가장 큰 지연 개월 수와 임계경로 포함 여부를 함께 보고한다.

`construction-view.mjs`는 이 보고서를 읽기만 한다. 지도 새로고침이나 화면 표시가 현금, 공정, 확률, 계약 상태를 변경하지 않는다.

## 3. 플레이 흐름

1. 플레이어가 노선·역·차량기지 계획을 만든다.
2. 공구 편집기에서 구간 공구, 역 공구, 차량기지 공구를 만든다.
3. 수직구·작업장·자재 적치장·공사용 도로·차량 반입 후보를 선택한다.
4. `공구 연동`을 실행해 현재 계획의 통합 공정표에 공구를 연결한다.
5. 월 진행 시 기존 통합 공정표가 갱신되고 지도는 공구별 상태·진척·지연을 표시한다.
6. 사건이 기록되면 사고·민원·자재 부족 마커가 해당 공구에 표시된다.

단순히 공구를 보거나 편집하는 동작은 경영 상태를 바꾸지 않는다. 명시적인 `공구 연동`만 런타임 저장 상태를 변경한다.

## 4. 저장과 복원

- 공정표에 연결된 공구와 후보 선택은 `ManagementGame` 저장 자료에 포함된다.
- `constructionMarkers`도 저장·복원된다.
- 화면 표시 모델인 `constructionView`는 저장 대상에서 제외된다.
- 지도 공구 편집 문서 자체는 현재 브라우저 `localStorage`에만 저장된다. 통합 세이브 파일로 합치는 작업은 별도 과제다.

## 6. 현재 한계

- 구간 공구의 진척은 아직 연결된 노선 토목 작업의 진척을 읽는다. 공구별 계약·예산·시공사를 따로 운영하는 단계는 아니다.
- `existingFacilityCrossingCount`는 공간상 겹침일 뿐 소유권이나 시설 재사용 가능성을 뜻하지 않는다.
- 사건 마커를 기록하는 API는 있지만, 사고·민원·자재 부족의 발생 확률과 비용·공기 영향은 아직 자동 계산하지 않는다.
- 지도 공구 문서와 경영 세이브의 원자적 통합 저장은 아직 없다.
- 월별 간트 차트와 공구별 상세 계약 화면은 아직 없다.
