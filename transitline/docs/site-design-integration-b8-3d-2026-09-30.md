# B8-3D — 3D 역 현장 편집 완전 연동

작성일: 2026-09-30
담당: Codex

## 목적

3D 현장 편집기의 결과를 단순 시각화로 끝내지 않고, CityPack의 실제 공간자료로 다시 검사한 뒤 경영 엔진의 설계변경 절차로 넘긴다. 지도는 충돌 사실만 계산하고 비용·공기·승인 여부는 경영 엔진만 결정한다.

## 구현 결과

### 실제 공간자료 공용화

- `loadPack()`이 선택 자료인 `obstacles.json`과 `barriers.json`을 읽는다.
- `spatialContextFromPack()`이 건물과 수역을 공용 공간 컨텍스트로 바꾼다.
- 같은 공간 컨텍스트를 노선, 역, 차량기지, 공사 공구, 공사 사건, 작업면, 3D 역 현장 편집기가 공유한다.
- 기존망 유지 모드는 기존 철도 레이어를 포함하고, 백지 모드는 빈 기존 철도 레이어를 사용한다.
- 자료가 없거나 범위 밖이면 `null`과 사유를 유지하며 0이나 안전으로 바꾸지 않는다.

### 3D 편집 충돌 재검사

부모 화면의 `site-design-bridge.mjs`가 `buildStationSite()`를 재사용해 다음을 다시 계산한다.

- 역 본체의 건물·수역 충돌
- 이동하거나 새로 추가한 출입구의 충돌
- 삭제한 출입구의 검사 대상 제외
- 이동·확대한 작업구의 건물·수역 충돌

결과는 `transitline.site-design-collision-result/1`로 편집기에 돌아가며 `true`, `false`, `null`을 구분한다.

### 주변 도시 표시

3D 세션을 열 때 역 주변 350m의 다음 자료를 전달한다.

- 건물 폴리곤과 가능한 경우 높이
- 도로 선형(레이어가 있을 때)
- 수역 폴리곤
- 기존 철도 선형

멀리 떨어진 도형은 세션에 넣지 않아 렌더링 부하를 제한한다.

### 메시지 보안과 세션 무결성

- 허용된 세 가지 수신 스키마만 처리한다.
- `event.origin`, `event.source`, `sessionId`, `stationSiteId`를 검사한다.
- 잘못된 READY 메시지도 예외 없이 거부한다.
- iframe이 아닌 다른 창이 보낸 같은 origin 메시지도 처리하지 않는다.

### 경영 승인 실패 정리

설계변경안을 만든 뒤 승인 단계에서 예산 부족 등으로 실패하면 해당 안을 즉시 `rejected`로 마감한다. 따라서 `proposed` 상태가 남아 다음 수정 제출을 영구적으로 막는 문제가 없다. 경영 엔진의 원자적 롤백은 그대로 유지한다.

## 현재 한계

- 도로는 현재 CityPack에 충돌 계산용 선형 레이어가 없으므로 대부분 표시되지 않는다. PMTiles 시각 자료를 곧바로 경영 판정 자료로 간주하지 않는다.
- 도쿄 건물 충돌 자료는 팩에 포함된 제한 구역만 다룬다. 범위 밖은 `outside-coverage`다.
- 이번 실행 환경에는 연결된 브라우저가 없어 실제 클릭 자동화는 재실행하지 못했다. 모듈·통합 테스트와 구문 검사까지는 모두 통과했다.
- 3D 대상 최초 선택의 고각도 레이캐스팅 정밀도 한계는 기존과 동일하다. 배치·이동·회전·작업구 조작은 MapLibre 좌표 기반이라 이 문제를 우회한다.
