# B12-6 직통 연락선·분기기 건설사업

## 목표

B12-5까지는 서로 물리적으로 붙은 노선만 실제 직통 운행선으로 만들 수 있었다. B12-6은 떨어져 있거나 외부망 접속이 확인되지 않은 경계를 즉시 `physicalConnection=true`로 고치지 않고, 별도의 연락선 건설사업으로 처리한다.

- 지도 사실: `transitline.through-handover-site-geometry/1`
- 경영 사업: `transitline.through-handover-project/1`
- 연결 키: `throughRouteId + routeGeometryRevision + handoverId`

지도 원본은 불변이다. 완공된 사업은 위 세 키에 대한 별도 접속확인 기록을 만들며, `through-service` 심사는 그 기록이 현재 경로 개정과 정확히 일치할 때만 경계를 `joined`로 인정한다. 노선 형상이 바뀌어 `geometryRevision`이 바뀌면 이전 공사 확인은 자동으로 무효다.

## 플레이 흐름

```text
지도에서 연락선 후보 설계
→ 2026년 JPY 개략 견적·기술검토
→ 관련 인프라 소유자 전원 허가
→ 시공사 경쟁입찰
→ 낙찰·공사비 자금예약·착수금 지급
→ 월별 공사·기성지급·지연위험
→ 3개월 통합검사
→ 해당 경로 개정본의 접속 완료
→ 직통 서비스 재심사·승인
```

## 비용과 기간

구조별 2026년 기준 직접 공사비는 다음 단가에서 시작한다.

| 구조 | JPY/m | 기준 생산성 |
|---|---:|---:|
| 지상 | 3,000,000 | 35 m/월 |
| 개착 | 9,000,000 | 18 m/월 |
| 터널 | 18,000,000 | 12 m/월 |
| 고가 | 11,000,000 | 22 m/월 |
| 교량 | 15,000,000 | 14 m/월 |

여기에 분기기, 전력·신호, 도로·수역·기존철도 횡단, 건물 이전, 외부 철도회사 인터페이스, 설계·허가, 국가별 건설비 계수와 예비비가 붙는다. P50과 P90을 분리하고, 기간은 설계·허가·시공·통합검사로 나눈다.

핵심 길이가 `null`이면 비용과 기간도 `null`이며 사업 상태는 `needs-information`이다. 횡단·건물 수가 미상일 때는 0으로 바꾸지 않는다. 공간 사실은 계속 `null`로 보존하고, 견적에만 각 1건의 보수적 가정을 적용해 `estimateAssumptions`에 공개한다. 외부망 접속 형상이 확인되지 않은 상태에서는 입찰할 수 없다.

## 기술·허가 관문

- 차량·선로 기술 프로필의 최소 곡선반경보다 작은 경우 입찰 불가
- 최대 허용 구배보다 가파른 경우 입찰 불가
- 외부 선형과의 실제 접속이 충돌하거나 미확인인 경우 입찰 불가
- 필요한 인프라 소유자가 여러 곳이면 전원이 허가해야 `permitted`
- 지도 작업공간 미선정 같은 비핵심 미확인은 조건과 예비비로 공개

## 시공사와 회계

기존 `constructionContractors` 시장을 재사용한다. 구조에 맞는 공종·장비, 잔여 수주용량, 재무능력이 있는 회사만 입찰한다. 평가 방식은 종합평가가 기본이고 최저가 방식도 선택할 수 있다.

낙찰 시 P50 계약금 전액을 원장에 commitment로 예약하고 10%를 착수금으로 지급한다. 이후 실제 공정률만큼 지급하며 완공 때 계약금과 시공사 장비·백로그를 정확히 한 번 해제한다. 취소하면 이미 지급한 금액은 `sunkCostJPY`로 남고 미집행 예약만 해제한다.

## 저장·호환

`ManagementGame.snapshot()`에 `throughHandoverProjects[]`와 단조 증가 ID 시퀀스를 저장한다. 구버전 저장본에 키가 없으면 빈 배열과 다음 번호 1로 복원한다. `ScenarioRuntime.report()`는 사업 목록을 읽기 전용으로 노출한다.

## 현재 한계와 다음 연결

- 지도 계약이 본선에 합쳐졌으며 경영 모듈은 정본 필드 `buildingIntersectionCount`와 `physicalConnectionEvidence.connected`를 우선 읽는다. 세 팩의 실제 예제 12개를 경영 견적에 직접 넣는 계약 적합성 테스트가 `null`과 명시적 0, stale 경로를 구분한다. 구저장본 호환을 위해 종전 별칭은 읽기 전용으로만 남긴다.
- 현재 통합검사는 기간 관문이며 별도 재검사 실패 사건은 아직 없다.
- UI 버튼과 지도 후보 선택 연결은 지도 계약 병합 후 붙인다.
- 기존 본선 대공사와는 별도 소규모 사업으로 회계 처리한다. 향후 B12-7에서 야간 선로점유·운행중단·대체수송 손실을 추가한다.
