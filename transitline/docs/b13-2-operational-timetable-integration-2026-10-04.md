# B13-2 실제 운행선 시간표 연결

## 결과

B13-1의 선로 용량 시간표를 실제 게임의 역·선로·운행선 및 열차 배차에 연결한다. 활성 시간표가 있는 요일에는 기존의 단순 `시간당 운행횟수` 간격 대신 승인된 출발 시각에만 열차가 출발한다.

## 실제 선로 변환

`buildOperationalRailwayTimetableInput()`은 다음 경계를 지킨다.

- 서비스의 `operationalLineId` 또는 직통운행 바인딩으로 실제 운행선을 찾는다.
- 운행선의 연속 역 쌍마다 정확히 하나의 `trackSegment`가 있어야 한다.
- `trackSegmentIds` 배열 순서를 믿지 않고 역 양단으로 실제 순서를 복원한다.
- 같은 역 쌍에 선로가 없거나 둘 이상이면 임의 선택하지 않고 거절한다.
- 역 양단만 같은 병렬 선로도 같은 선로로 보지 않는다. 활성화 때 승인 경로의 `sectionId`가 실제 운행선의 구간 ID와 정확히 일치해야 한다.
- 저장된 선로 방향이 뒤섞여 있어도 `sectionDirections[]`로 각 구간의 실제 진행 방향을 보존한다.
- 구간 운전시분이 없으면 길이와 해당 구간을 쓰는 가장 느린 서비스의 영업속도로 계산한다.
- 최소시격과 단·복선 자료가 없으면 심사를 거절한다. 플레이어·시나리오가 `infrastructureAssumptions`로 두 값을 명시해야만 계산하며, 시간당 용량은 그 명시 시격으로부터 계산한다. 모든 대체값은 `operationalFacts.assumptions[]`에 공개한다.
- 공사 폐쇄 시간은 호출자가 `closureWindowsBySectionId`로 명시한 경우에만 넣는다. B12 공사 위치를 선로구간으로 임의 추정하지 않는다.
- 사용한 실제 선로의 양단·길이·운전시분·단복선·최소시격·용량·분기 자원을 결정론적 지문으로 만든다. 심사 뒤 이 사실이 바뀌면 활성화를 거절한다.

## 구간별 방향

B13-1 경로에 선택 필드 `sectionDirections[]`를 추가했다. 생략하면 기존처럼 경로 전체의 `direction`을 사용하므로 구저장본과 기존 호출은 그대로 동작한다. 실제 선로 어댑터는 구간별 방향을 명시하여 원본 선로 양단의 저장 방향이 섞인 경우도 정확히 예약한다.

## 활성화와 열차 배차

`ScenarioRuntime.activateRailwayTimetable()`은 다음을 하나의 원자적 작업처럼 처리한다.

1. 경영 시간표 활성화
2. 서비스와 실제 운행선 연결 확인
3. 승인 경로의 역 순서와 실제 운행선 순서 확인
4. 요일별 출발 시각을 운행선에 적용

어느 단계든 실패하면 경영 상태와 운행 상태를 모두 이전 스냅샷으로 복구한다. 같은 요일의 새 시간표는 이전 시간표를 전역적으로 대체하며, 새 시간표에서 빠진 서비스의 오래된 링크와 운행선 배차표도 제거한다.

열차 시뮬레이션은 다음과 같이 동작한다.

- 현재 요일에 활성 시간표가 있으면 승인된 outbound 출발만 실행한다.
- outbound 한 편마다 같은 `dutyId`의 승인된 inbound 한 편이 반드시 있어야 한다. 열차는 종점 도착 후 그 inbound 출발시각까지 대기한 뒤 돌아온다. 단순 시각 순서로 서로 다른 왕복을 짝짓지 않는다.
- 편도만 승인됐거나 복편이 용량 심사에서 탈락한 시간표는 실제 운행에 활성화할 수 없다.
- 짧은 프레임 지연으로 출발 시각을 지나도 해당 검사 구간 안의 출발은 정확히 한 번 실행한다.
- 운행 중단 중 놓친 출발은 재개 시 몰아서 출발하지 않는다.
- 프레임 지연 허용치는 기본 1분이다. 그보다 오래 지난 출발은 현재 시각에 뒤늦게 열차를 생성하지 않고 `missedDepartures`로 센다.
- 시간표가 없는 요일은 기존 주파수 기반 배차를 유지한다.
- 기존 열차 모델이 한 편성을 왕복시키므로 inbound 경로는 별도 편성을 만들지 않고 같은 편성의 종점 대기·복편 출발 권한으로 사용한다.

적용 상태는 `report().operationalTimetableApplications`와 통합 저장본의 운행 상태에 포함된다.

로드할 때 활성 경영 시간표를 실제 선로에 다시 검증·적용한다. 구버전 시간표처럼 현재 운행 계약을 만족하지 못하면 저장본 전체를 거절하지는 않되, 해당 요일의 주파수 기반 우회 운행을 빈 배차표로 차단하고 `report().operationalTimetableWarnings`에 이유를 남긴다.

## 현재 한계와 다음 단계

- 공휴일 달력과 `holiday` 시간표 선택은 아직 운행 시뮬레이션에 연결하지 않았다. 따라서 경영 심사는 가능하지만 실제 운행 활성화는 명시적으로 거절한다.
- 열차는 시간표의 구간별 운전시분이 아니라 기존 물리 이동 속도로 움직인다. B13-3에서 지연·대피·선행열차 간격을 실제 열차 위치에 적용한다.
- B12-7 점유 계획은 서비스 영향률까지만 계산한다. B13-3에서 명시적인 선로구간·시간창 연결을 추가한다.
- 승강장별 진로와 입환은 B13-M5 지도 사실 계약을 받은 뒤 B13-4에서 연결한다.
