# A6-2 공사 사건·대응 경영 엔진 구현 보고서

- 기준일: 2026-09-28
- 통화·가격 기준: 2026년 일본 엔(JPY)
- 범위: 공구별 사건 발생, 대응 선택, 비용·공기·안전·품질·평판 결과, 저장·복원
- 주의: 아래 확률과 대응 계수는 공식 사고 통계가 아니라 게임 밸런스용 초기값이다. 향후 실증자료로 교정할 수 있도록 한 모듈에 분리했다.

## 1. 구현 결과

`ConstructionSiteGeometry`가 통합 공정표에 연결된 사업은 공구별 사건 엔진을 사용한다. 공구가 없는 이전 사업은 기존 프로젝트 단위 임의 지연을 유지한다. 공구가 있는 사업에서는 구형 임의 지연을 실제 결과에 적용하지 않아 위험을 중복 계산하지 않는다.

지원 사건은 다음 8종이다.

| 사건 | 주요 공간·공정 요인 |
|---|---|
| `cost-inflation` | 모든 활성 공구에 적용 가능한 비공간 사건 |
| `material-shortage` | 모든 활성 공구 |
| `incident` | 급경사, 수역 횡단 등 |
| `complaint` | 주거지 인접, 건물 충돌 |
| `permit-delay` | 기존 시설 겹침 등 관계기관 협의 요소 |
| `utility-conflict` | 개착 공구, 지장물 자료 미확인 |
| `unexpected-ground` | 터널·개착, 지하수·연약지반 자료 미확인 |
| `access-blocked` | 차량 반입 후보가 없는 공구 |

지도 자료가 없다는 사실은 위험을 확정하지 않는다. 낮은 자료 품질과 다수 결측은 작은 불확실성 가산치로만 사용하며, 원본 `null`과 `unknownReasons`는 변경하지 않는다.

## 2. 월별 발생 모델

공사 중인 공구마다 월 기본 발생확률 0.6%에 다음 값을 곱한다.

- 국가의 기존 분쟁·지연 보정치
- 시나리오 난이도의 `delayFactor`
- 터널·개착 여부
- 공간 위험 플래그 수
- 자료 품질과 결측 불확실성

최종 월 확률은 공구당 최대 8%로 제한한다. 같은 공구에는 미해결 사건이 있거나 최근 2개월 안에 사건이 발생했다면 새 사건이 나오지 않는다. 한 통합 공정표에서는 한 달에 최대 한 사건만 생성한다.

사건 종류와 심각도(`minor`, `moderate`, `major`)는 별도 결정론적 난수 스트림에서 뽑는다. 이 스트림은 차량 제작·차량기지·기존 공사 난수와 분리되어 새 기능이 기존 시뮬레이션 결과를 우연히 바꾸지 않으며, 세이브 파일에 상태가 저장된다.

## 3. 사건과 공정표

사건은 연결 공구의 미완료 작업 중 다음 순서로 하나를 선택한다.

1. 진행 중인 임계경로 작업
2. 진행 중인 작업
3. 임계경로의 미착수 작업
4. 나머지 미완료 작업

중간·대형 사건은 발생 즉시 피할 수 없는 지연을 공정표에 기록한다. 대응 선택에서 발생한 추가 지연도 같은 작업에 별도 지연 사건으로 기록한다. 따라서 기준 공정은 보존되고 예상 공정과 개통 예정일만 변경된다. 비임계 공구의 지연은 여유시간 안에서 흡수될 수 있으므로 항상 개통 지연과 같지는 않다.

## 4. 대응 선택

각 사건에는 세 가지 대응책이 있다. 예시는 다음과 같다.

| 사건 | 비용 중심 | 균형·안전 중심 | 지연·평판 위험 선택 |
|---|---|---|---|
| 사고 | 긴급 복구 | 전면 중지·원인 조사 | 최소 법정조치 |
| 민원 | 방음·진동 저감과 주민지원 | 야간·휴일 제한 | 현 공정 유지 |
| 자재 부족 | 프리미엄 조달 | 승인 대체 자재 | 공급 회복 대기 |
| 지장물 | 이설 | 국부 재설계 | 관계기관 협의까지 중지 |
| 예상 외 지반 | 지반 보강 | 시공법 변경 | 추가 조사 |
| 접근 차단 | 대체 반입로 | 관리자 협의 | 반입 중지 |

대응 결과는 다음 값에 반영된다.

- 즉시 지출 JPY
- 추가 지연 개월
- 공사 안전
- 품질
- 지역사회 신뢰와 회사 평판
- 시공사 관계

비용은 사업 전체 금액에 바로 일정 비율을 곱하지 않고, 해당 공구가 차지하는 공정 기간 비중으로 공구 노출액을 만든 뒤 사건·대응·심각도 계수를 적용한다. 백만 엔 단위로 반올림한다.

플레이어가 한 달 안에 선택하지 않으면 사건별 보수적 기본 대응이 자동 적용된다. 현금이 부족하면 기본 대응 대신 감당 가능한 대응 중 비용이 가장 낮은 안을 선택한다. 직접 선택한 대응의 현금이 부족하면 거래 전체가 롤백된다.

## 5. 지도·화면 계약

`ScenarioRuntime.report()`는 다음을 반환한다.

```js
{
  constructionEvents: ConstructionEvent[],
  constructionMarkers: [{
    eventId,
    constructionSiteId,
    kind,
    severity,
    status,
    location,
    candidateRef,
    message
  }]
}
```

물가 상승은 특정 위치를 갖지 않는 경영 사건이므로 지도 마커를 만들지 않는다. 나머지 사건은 선택된 공사 후보의 위치가 있으면 그 좌표를 사용하고, 없으면 `location: null`로 전달한다. 클루드의 영향권 지도 시스템이 이후 실제 위치 또는 공구 중심점 표시를 담당한다.

마커 상태 어휘는 `unresolved`(해결 전), `responding`(공간 대응 후보 적용), `resolved`(경영 대응 완료), `ignored`(의도적으로 무시) 네 가지다. `constructionPackages`와 `constructionMarkers`는 중첩하지 않고 별도 최상위 자료로 반환하며 `constructionSiteId`로 연결한다.

지도에서 선택한 대체 수직구·작업장·적치장·진입로는 `ConstructionImpactGeometry`로 다시 엔진에 전달된다. 주요도로 접근 가능 여부, 대체 후보 거리, 주거지 인접 여부에 따라 각 대응안의 비용과 추가 지연이 다시 계산된다. 후보 선택만으로 사건이 해결되지는 않으며 상태가 `responding`으로 바뀐 뒤 플레이어가 최종 경영 대응을 선택해야 한다.

시나리오 화면에는 `공사 사건·대응` 패널을 추가했다. 각 대응 버튼에서 비용, 추가 지연, 안전, 품질, 평판 변화를 선택 전에 볼 수 있다. 해결 뒤에는 실제 선택과 결과를 표시한다.

## 6. 저장과 원자성

- 사건 목록과 대응 결과
- 사건 전용 난수 상태
- 공사 안전·품질·지역 신뢰·시공사 관계
- 지도 마커의 해결 상태
- 공정 지연 기록과 원장 지출

위 값은 모두 `ManagementGame` 저장 자료에 포함된다. 현금 부족이나 잘못된 중복 대응처럼 명령이 실패하면 사건, 현금, 평판, 공정표가 함께 이전 상태로 돌아간다.

`eventId`는 게임 안에서 단조 증가하는 `construction-event:<sequence>` 형식이다. 해결·무시된 사건을 삭제하거나 번호를 재사용하지 않으며 다음 번호도 세이브에 포함한다. 이전 개발 세이브에 다음 번호가 없으면 저장된 사건 ID의 최댓값 다음 번호로 복원한다.
