# 차량기지 이후 작업 분담·인수인계

- 기준일: 2026-09-26
- 가격·통화: 2026년 JPY
- 기본 국가: 일본, 비교 프로필: 대한민국
- 목적: Codex와 Claude가 같은 파일을 동시에 수정하지 않고 다음 시스템을 순서대로 완성한다.
- 다음 주력 목표: **시스템 2 — 역·승강장·출입구·환승·회차**
- Codex 진행상태: **A0·A1·A2·A3 완료**, 다음 재개점은 A4

## 1. 현재 완료 기준선

현재 코드는 다음 수직 흐름을 한 번 끝까지 실행할 수 있다.

```text
사업 공고·조사·Bid/No-Bid
→ 경쟁입찰·우선협상·계약
→ 계획 승인·철도 건설
→ 차량 발주·제작·시험·인수
→ 차량기지 후보 비교·지역협의·다년 공사
→ 개통 준비 판정
→ 영업·운임·공공대가·KPI·운영비 정산
→ 통합 저장·복원
```

2026-09-26 마지막 전체 확인 기준 `npm test`는 **143/143 통과**했다. Claude가 만든 지도 쪽 산출물에는 `PlanGeometry`, `DepotSiteGeometry`, 지도 편집·표시, 예제와 계약 테스트가 포함된다. Codex 쪽에는 경영 커널, 사업수주, 건설, 차량, 차량기지, 운영경제, 금융, 경쟁회사, 시나리오 런타임이 있다.

작업 트리는 두 담당자의 변경이 함께 있는 미커밋 상태다. 임의로 reset, checkout, 대량 삭제, 자동 포맷을 하지 않는다. 루트의 이름이 `5`인 추적되지 않은 파일도 건드리지 않는다.

## 2. 역할 경계

| 구분 | Claude | Codex |

| 책임 | 지도 편집, 지형·건물·도로·수역·기존망 등 공간 사실, 공간 ID, 지도 표시 | 규칙, 기술 호환성, 비용, 기간, 허가, 계약, 현금, 확률, 운영, AI 경쟁 |
| 출력 | 공간 사실과 결측 사유 | 판단, 예상범위, 공사·운영 상태와 장부 |
| 금지 | 비용·점수·주민반대·공기·사업성 계산, `management/**` 수정 | 원자료를 임의 생성하거나 지도 결측을 사실상 0으로 취급 |
| 공통 | 버전 있는 JSON 계약, 안정 ID, `null`+결측 사유, 고정 예제, 계약 테스트 | 버전 있는 JSON 계약, 안정 ID, `null`+결측 사유, 고정 예제, 계약 테스트 |

같은 파일을 양쪽이 동시에 고치지 않는다. 계약 변경이 필요하면 먼저 문서와 테스트를 고치고, 각 담당자가 자기 영역의 어댑터만 수정한다.

## 3. Claude에게 시킬 일

### C0. 기존 지도 통합 미완료 정리

1. 그린 노선과 차량기지 후보에 안정 `key`를 UI 상태와 저장본에 보존한다.
2. 지도 출력의 결측 정책을 `null`과 `unknownReasons`로 일관되게 유지한다.
3. 엔진의 `PlanAssessment`를 지도 화면의 `setEngineReport`에 연결해 오류·경고·공사 상태가 실제 경영 결과를 표시하게 한다.
4. 취소와 공사 중단을 같은 표시로 쓰지 않도록, 엔진 상태 계약이 제공되면 별도 색과 범례를 둔다.
5. 이 단계에서는 `engine/src/management/**`를 수정하지 않는다.

### C1. `StationSiteGeometry` 공간 계약

역 후보 하나에 대해 아래의 **공간 사실만** 계산하는 계약을 만든다.

- 안정 `stationSiteId`, 연결 `planId`와 `segmentId`, 좌표계와 데이터 출처
- 선로 중심선 방향, 지표고, 계획 선로고 또는 계획 깊이
- 역 본체 후보 다각형과 회전 방향, 길이·폭·면적
- 주변 도로 폭·등급, 건물 교차 수, 수역 교차, 경사
- 출입구 후보점과 각 후보의 도로변 위치·공공용지 여부·건물 충돌
- 기존역·타사 노선과의 최단 공간거리 및 환승 연결 후보
- 수요지점까지의 보행 접근거리
- 공사용 작업구·장비 반입 후보 공간
- 각 값의 `dataQuality`, `unknown[]`, `unknownReasons`

지도 모듈은 역 종류, 승강장 형식, 공법, 공사비, 공사기간, 수용력, 환승점수, 보상비를 결정하지 않는다.

### C2. 역 후보 편집기와 표시

1. 역 본체를 이동·회전·길이·폭 조정하고 삭제·복원할 수 있게 한다.
2. 출입구와 환승통로 후보를 추가·이동·삭제할 수 있게 한다.
3. 같은 저장본을 다시 열어도 ID가 유지되게 한다.
4. 역 본체·출입구·환승 후보·공사 위험 마커를 서로 다른 레이어로 표시한다.
5. 경영 엔진이 반환한 `불가 / 조건부 / 승인 / 공사 중 / 완공` 상태는 읽기 전용 오버레이로 표시한다.

### C3. 예제와 계약 테스트

도쿄와 합성 팩에 다음 고정 예제를 만든다.

- 지상 상대식 일반역
- 고가 섬식 일반역
- 얕은 지하 개착역
- 깊은 지하역
- 기존역 환승역
- 종착·회차 후보역
- 건물 충돌 또는 출입구 확보 실패 후보
- 일부 공간 레이어가 없어 결측값이 생기는 후보

완료 조건은 동일 입력의 바이트 단위 동일 출력, 그리기 순서와 명칭에 독립적인 ID, 저장·복원 후 ID 유지, 결측을 0으로 만들지 않음, 지도 모듈이 경영 상태나 현금을 바꾸지 않음이다.

## 4. Codex가 할 일

### A0. 차량기지 결측값 경계 수정 — 최우선

**상태: 완료.** 구현 내용과 검증은
[역·승강장·동선 시스템 1차 구현 보고서](station-system-implementation-2026-09-26.md)에 기록했다.

현재 `depot-planning.mjs`의 `intersectedBuildingCount ?? 0` 등은 지도에서 `unknown`으로 넘긴 값을 실제 0건으로 바꿔 계산한다. 이를 먼저 고친다.

1. 원본 `null`을 보존한다.
2. 계산이 필요한 경우 명시적 보수 추정값을 별도 사용한다.
3. 결과에 `imputedInputs` 또는 동등한 가정 목록과 근거를 반환한다.
4. 결측 후보는 실제 0건으로 조사된 후보보다 불확실성·P90이 높아야 한다.
5. 명시적 0과 결측 `null`이 다른 결과를 내는 회귀 테스트를 추가한다.
6. Claude의 `unknownReasons`를 진단 결과에 전달한다.

### A1. 역·승강장 기술 모델

**상태: 완료.** `StationPlan` v1과 기술 호환성 검사를 구현했다.

`StationPlan`과 `PlatformPlan`을 별도 객체로 만들고 다음을 구현한다.

- 지상·고가·개착 지하·실드 지하·대심도 역
- 상대식·섬식·2면 3선·2면 4선·종착 두단식 기본 배선
- 소형·중형·대형 철제차륜, 리니어, AGT, 모노레일의 승강장 호환성
- 편성 길이, 정차 여유, 승강장 유효길이·폭·높이·간격
- 홈도어와 차량 문 위치, 정위치 정차, 회차설비 조건
- 현재 편성용 마감 길이와 장래 증결용 구조 길이 분리

### A2. 출입구·역 내부 동선·환승·용량

**상태: 완료.** `StationAccessPlan` v1과 흐름·혼잡·정차·대피 계산을 구현했다.

- 승강장 → 계단·에스컬레이터·엘리베이터 → 대합실 → 개찰 → 출입구 흐름
- 시간대별 방향별 승객량, 병목, 대기열, 혼잡과 안전 한계
- 무장애 경로와 비상피난 관문
- 출입구 수와 위치에 따른 접근시간·수요·토지권리 비용
- 환승거리, 층간 이동, 개찰 내·외 환승과 환승저항
- 혼잡이 정차시간, 열차 지연, 수요와 KPI에 미치는 영향

### A3. 역 공법·원가·기간·권리

**상태: 완료.** 지도 독립 내부 컨텍스트, 공법 판정, 물량·권리·P50/P90와
선행 공정망을 구현했다. 실제 `StationSiteGeometry` 어댑터는 Claude 계약
확정 후 A4 통합 때 연결한다.

- 구조와 공법을 분리해 개착, 실드 확대, NATM 등 적용 가능 조건을 판정한다.
- 역 본체, 출입구, 환승통로, 환기·방재, 엘리베이터, 홈도어를 별도 물량·비용으로 계산한다.
- 지상 토지, 구분지상권·대심도, 건물 출입구 설치협약을 구분한다.
- 조사 수준별 P50/P90, 결측 가정, 국가별 단가·승인·분쟁 기간을 반영한다.
- 작업구, 도로점용, 지장물 이설, 기존선 근접공사의 선행조건을 둔다.

### A4. 건설·계약·개통 통합

1. 역별 공사를 토목, 구조, 건축, 궤도·전력·신호, 설비, 시험 공정으로 나눈다.
2. 독립 공구는 병행하고 선행조건과 공유 작업팀은 중복 사용하지 못하게 한다.
3. 시공사 제안가격·기술·안전·수주잔량·공기를 평가해 계약한다.
4. 설계변경, 물가상승, 사고, 지장물, 주민·상인 협의가 돈과 임계경로를 바꾸게 한다.
5. 역·승강장·출입구·피난·환승·회차가 준비되지 않으면 개통을 막는다.
6. 취소, 일시중단, 재개, 단계개통을 서로 다른 상태로 저장한다.

### A5. UI와 설명 가능성

플레이어가 후보를 선택할 때 아래를 한 화면에서 비교하게 한다.

- 선택한 구조·배선·승강장과 지원 가능한 차량
- P50/P90 사업비와 예상 개통 범위
- 토지·지하권·민원·지장물·기술 결측
- 시간대별 예상 혼잡과 병목 위치
- 환승시간과 출입구별 접근 수요
- 공정 임계경로와 현재 지연 원인

모든 경고는 “왜 불가한지”와 “무엇을 바꾸면 가능한지”를 함께 반환한다.

### A6. 검증·보정

- 일본과 한국의 동일 역 후보 비교
- 명시적 0 대 결측 `null` 비교
- 차량·승강장·홈도어 불일치 거절
- 짧거나 좁은 승강장의 용량 저하
- 출입구 하나 폐쇄 시 대피·혼잡 재계산
- 환승통로 장거리화에 따른 수요 감소
- 지상·고가·얕은 지하·대심도 비용·기간 순서 검증
- 배속과 저장·복원 뒤 공정·현금·승객 결과 일치
- 전체 `npm test`와 팩 검증 통과

## 5. 실행 순서와 서로 기다릴 지점

```text
1. Codex A0 결측 처리 수정
   └─ Claude C0 기존 지도 통합 정리와 병행 가능

2. Claude C1 계약 초안 + 고정 예제 1개
   └─ Codex가 계약 검토 후 A1 입력 어댑터 확정

3. Claude C2~C3 편집·표시·전체 예제
   └─ Codex A1~A3 계산 엔진과 병행

4. Codex A4 통합
   └─ Claude는 지도 오버레이가 엔진 결과를 읽도록 연결

5. Codex A5~A6 UI·전체 회귀검증
```

두 담당자의 첫 동기화 지점은 `StationSiteGeometry` 계약이다. Claude가 임의로 비용 필드를 넣거나 Codex가 지도 레이어를 직접 읽지 않는다.

## 6. 역 시스템 다음 순서

역 시스템이 완료된 뒤에는 아래 순서로 진행한다.

1. 공법·공정·시공사·계약을 공구 단위로 심화한다.
2. 차량 성능·에너지·고장·검사 주기를 심화한다.
3. 제작사 생산라인·부분납품·불량·보증·설계변경을 심화한다.
4. D2 중정비기지·외부 위탁정비·공유기지를 확장한다.
5. 리니어 또는 AGT를 완전한 두 번째 철도 시스템으로 추가한다.
6. 모노레일·대심도·복합환승을 추가한다.
7. 버스 노선과 철도 피더·대체수송을 연결한다.

## 7. 컴팩트 이후 Codex 재개 지점

다음 Codex 세션은 이 문서를 먼저 읽고 **A4 건설·계약·개통 통합**부터 시작한다. A0~A3의 구현 결과는 [역·승강장·동선 시스템 1차 구현 보고서](station-system-implementation-2026-09-26.md)를 따른다. Claude의 `StationSiteGeometry` 계약이 도착하면 내부 `StationConstructionContext` 어댑터를 계약 테스트로 연결하고, 필드명을 추측해서 덮어쓰지 않는다.
