# B12-2 구간별 기술 호환성 1차 구현

## 목표

B12-1 직통 서비스가 차량의 `profileId` 한 개만 비교하던 판정을 세부 기술 인터페이스로 교체한다. 같은 궤간이거나 같은 “지하철”이라는 이유만으로 직통 가능 판정을 내리지 않는다.

순수 계약은 `transitline.technical-compatibility/1`이며 구현은 `engine/src/management/technical-compatibility.mjs`에 있다.

## 검사 항목

1. 주행·안내 방식
2. 궤간(AGT·모노레일처럼 적용되지 않는 시스템은 명시적으로 `not-applicable`)
3. 집전 방식, 교류·직류, 전압의 조합
4. 차량 폭과 시설 차량한계
5. 차량 축중과 시설 허용축중
6. 차량 최소곡선반경과 구간 곡선 조건
7. 구간 최대경사와 차량 등판·제동 성능
8. 지상·차상 신호체계 교집합
9. 승강장 높이 범위
10. 차량 문 배열
11. 편성 차량 수 범위
12. 차량기지 정비체계

판정은 `possible / conditional / impossible / unknown` 네 값이다. 결측 `null`은 0이나 안전으로 바꾸지 않고 `unknown`으로 남긴다. 여러 궤간·전원·신호를 실제 지원 목록에 넣은 차량만 다중 시스템 차량으로 인정한다.

## 연결 범위

- `ThroughService.legs[].technicalCompatibility`에 구간별 상세 판정을 저장한다.
- 상세 위반·조건·결측 사유는 직통 서비스 전체 판정으로 전달한다.
- B11-3 선로사용 공모도 같은 판정기를 사용한다. `conditional`과 `unknown`은 기술 적합으로 통과시키지 않는다.
- 영업 자력운행은 모든 필수 기술조건을 검사한다.
- `towed-transfer`는 전원·신호 불일치만 견인차와 별도 승인 필요 조건으로 낮춘다. 궤간·차량한계·축중 등 물리 불일치는 그대로 불가능이다.

## 기준값의 성격

이번에 `TECHNICAL_PROFILES`와 `VEHICLE_MODELS`에 추가한 세부값은 기존 게임 내 규격 묶음을 내부적으로 일관되게 확장한 2026년 게임 기준값이다. 실제 특정 일본 노선의 완전한 설비 사양이라고 주장하지 않는다. 외부 노선 자료가 들어오면 `technicalSpecification`으로 프로필 기본값을 덮어쓰며, 자료가 `null`이면 자료 부족으로 판정한다.

## 제외 및 다음 단계

- 차량 개조비·추가 제작기간·승인시험비는 계산하지 않는다.
- 실제 구간별 곡선·경사 최댓값을 지도 선형에서 집계하는 작업은 별도 지도 계약이 필요하다.
- 승강장 간격·곡선 편위·홈도어 정위치 정차는 기존 `StationPlan` 상세 판정을 유지한다.
- 차량기지 입출고선의 실제 연속 경로와 정비설비 용량은 기존 차량기지 시스템과 후속 연결한다.
- B12-2 다음 단계에서는 지도/팩이 외부 노선의 세부 기술사양을 공급하는 계약과 차량 개조·승인 경제성을 붙인다.
