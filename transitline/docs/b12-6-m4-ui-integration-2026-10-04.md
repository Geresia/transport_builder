# B12-6 M4 직통 접속부 UI 통합

## 결과

`ThroughHandoverSiteGeometry` 편집기를 실제 게임 지도와 직통운행 경영 패널에 연결했다. 플레이어는 저장된 직통 경로의 인계 지점을 선택해 양쪽 접속점, 연락선 경유점, 분기기, 작업구역, 구조형식과 설계구배를 편집할 수 있다.

## 지도 흐름

1. 직통운행 패널에서 두 개 이상의 노선을 골라 직통 경로를 저장한다.
2. 하단의 `직통 접속부` 도구를 연다.
3. 경로의 접속 경계를 추가하고 양쪽 접속점과 연락선을 그린다.
4. 분기기·작업구역·구조형식·설계구배를 지정한다.
5. 지도는 접속 증거와 건물·수역·도로·기존철도 교차 사실만 계산한다.

연락선 표시 모델은 `throughHandoverView`라는 비열거 슬롯에 보관한다. 따라서 통합 저장의 운행 상태에 화면 전용 모델이 섞이지 않는다. 편집 문서는 계약 설계대로 팩별 `localStorage`에 보존된다.

## 경영 흐름

직통운행 경영 패널의 `직통 접속부 건설`에서 현재 지도 후보를 사업으로 제안할 수 있다.

- 기술 프로필 선택과 P50·기간·조건 표시
- 외부 인프라 소유자별 허가
- 시공사 경쟁입찰
- 우선순위 시공사 낙찰과 착수금 지급
- 월별 게임 진행에 따른 시공·검사·완공
- 완공 전 사업 취소와 매몰비용 처리

외부 소유자는 지도 계약의 `externalSides[].infrastructureOwnerId`를 정본으로 읽는다. 명시적 입력이 있으면 그것을 우선하며, 운영사 이름으로 소유자를 추정하지 않는다.

## 도구 상호배타

직통 접속부 도구는 노선·역·차량기지·공사공구 편집, 역 설계 선택, 공사 후보, 사건 대응, 작업면 도구와 동시에 활성화되지 않는다. 도구를 바꾸면 이전 도구의 포인터 소유권을 해제한다.

## 한계

- 현재 팩에는 외부 철도의 실제 선형이 없어 `externalAlignments`는 빈 입력이다. 외부선 측 접속 증거는 실제 선형 자료가 추가되기 전까지 `null`이다.
- 연락선 편집 문서는 자체 팩별 저장소를 사용하며 시나리오 통합 저장 버튼의 단일 페이로드에는 아직 포함하지 않는다.
- 공사 진행은 기존 월별 경영 사이클을 사용한다. 별도의 지도 공정 애니메이션은 아직 없다.
