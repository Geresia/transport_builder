# 01. 철도 규격·구조 형식·선로 구성·차량 호환성

- 작성일: 2026-09-23
- 상태: 사용자 검토용 상세 설계 초안. 기능 범위·수치 확정 및 코드 구현 전.
- 수치 후속: [2026년 JPY 초기 기준표](railway-system-baseline-2026.md) — 기준 연도·통화 확정, 비용·기술 확보·일정의 게임 가정값 추가.
- 상위 문서: [철도 기본요소 명세](railway-system-foundations.md)
- 목적: 플레이어가 자유롭게 그린 철도에 건설·운행·경영상 결과를 부여한다.
- 범위: 철도의 기술 규격, 구간별 구조, 선로 연결, 호환성 및 후속 시스템에 전달할 조건.
- 제외: 지도 편집 구현, 자동차 도로 건설, 역 내부·개별 공법·차량 모델·제작사·기지의 상세 설계.

## 1. 설계 원칙

**철도는 노선 색깔 하나가 아니라, 여러 물리 시설 위에서 차량이 운행하는 시스템이다.**

아래 게임 규칙은 제안이다. 현실 사례는 출처를 붙여 구분하고, 실제 철도 설계나 인허가 지침으로 사용하지 않는다. 일본 기술기준은 성능 요건과 해석기준, 사업자의 실시기준을 구분하므로 하나의 곡선 반경·경사 숫자를 모든 노선의 법정 한계로 고정하지 않는다. [국토교통성 기술기준 안내](https://www.mlit.go.jp/tetudo/tetudo_fr7_000036.html)

- 도시·도로는 유지한다. 도로와 충돌하면 철도의 위치·높이·교차 방식을 검토한다.
- 기존망 연결과 독립망 신설을 모두 허용한다. 직통을 강제하지 않는다.
- 실제 건설된 시설, 공사 중 시설, 설계안을 구분한다. 설계 변경만으로 운행 중 시설이 바뀌지 않는다.
- 쉬운 조작과 단순한 물리 규칙은 다르다. 기본 설정 묶음으로 접근성을 높이되 결과는 같은 검증기를 사용한다.
- 각 기술의 장단점은 비용·기간·운행·유지관리로 나타낸다. 단순한 상위/하위 등급으로 만들지 않는다.

## 2. 혼동하면 안 되는 다섯 가지 분류

| 분류 | 예시 | 결정하는 것 |
|---|---|---|
| 주행 시스템 | 일반 철제차륜, 철제차륜 리니어, 모노레일, 고무차륜 안내궤도 | 차량과 주행로의 기본 호환성 |
| 서비스 성격 | 도시철도, 광역·통근, 지역·도시간, 고속 | 목표 수요·거리·운영 방식. 이것만으로 시설 규격이 정해지지는 않음 |
| 구조 형식 | 지상, 성토·절토, 고가, 교량, 지하 | 토목 시설과 주변 환경의 관계 |
| 선로 구성 | 단선, 복선, 복복선, 대피선·연결선 | 열차가 실제로 이동할 경로와 충돌 관계 |
| 정차 패턴 | 각역정차, 급행 등 | 어느 역에 정차하는지. 선로·차량 종류와 별개 |

LRT는 별도의 바퀴 원리로 취급하지 않고 차량·시설·운영 특성을 묶은 서비스 프로필로 다룬다. 도로 공유 구간은 별도 교통 상호작용 설계가 필요하므로, LRT 지원이 곧 도로 공유 운행 지원을 뜻하지 않는다.

같은 노선이 지상→고가→지하를 오가도 된다. 반대로 같은 지하철끼리도 기술 규격이 다르면 직통할 수 없다. 고속 서비스라는 이름만 붙여 속도가 올라가지 않는다.

## 3. 플레이어의 설계 순서

1. 기존 노선에 직통할지, 환승만 연결할지, 독립망으로 만들지 선택한다.
2. 기본 기술 규격 묶음을 선택한다. 직통 희망 노선이 있으면 그 규격을 불러와 비교한다.
3. 구간별 경로·높이와 지상/고가/지하 등의 구조를 정한다.
4. 단선/복선 등 선로 수와 분기·합류·대피·회차 경로를 배치한다.
5. 후보 차량 범위를 지정하여 곡선·경사·공간·전력·신호 호환성을 검사한다.
6. 예상 공사 물량, 비용·기간 범위, 운행 제약, 추가 조사가 필요한 부분을 확인한다.
7. 수정하거나 프로젝트로 넘긴다. 공사가 끝나도 개통 준비 검사를 별도로 거친다.

차량 구매는 나중이어도 되지만, 어떤 크기와 성능의 차량을 수용할지는 시설 설계에서 결정해야 한다. 아직 차량을 정하지 않았다면 허용 사양 범위를 명시하고, 실제 발주 시 다시 검사한다.

## 4. 기술 규격: 차량이 들어갈 수 있는 철도인가

### 4.1 선택·저장할 항목

| 항목 | 플레이어가 결정하는 내용 | 주요 결과 |
|---|---|---|
| 주행·추진 방식 | 철제차륜 일반 구동, 철제차륜 리니어 등 | 필요한 차량·주행로·추진 설비 |
| 궤간 | 좌우 레일 사이 규격 | 연결 가능한 차량군·기존망 |
| 급전 방식 | 가공전차선, 제3궤조, 비전철화 등 | 집전 장치, 시설 공간, 사용 가능한 차량 |
| 전기 규격 | 직류/교류, 전압, 교류 주파수 | 차량 전원 대응, 전력 계통 접속 |
| 공간 규격 | 차량 허용 단면과 시설의 통과 공간 | 차량 폭·높이, 곡선 통과, 터널 단면 |
| 하중 등급 | 허용 축중 및 구조물 하중 조건 | 투입 가능한 차량과 구조물 설계 |
| 선형 기준 | 곡선·경사·완화 구간과 목표 속도 | 운행 성능과 필요 부지 |
| 신호·보안 규격 | 호환 시스템 식별자, 지상·차상 설비 | 진입 가능 여부, 운행 간격 |
| 궤도 구조 | 자갈도상, 슬래브·직결 계열, 방진 옵션 | 건설 물량과 유지관리 특성 |

궤간, 차량한계, 건축한계는 서로 다른 개념이다. 차량한계는 차량의 허용 외곽, 건축한계는 안전한 운행을 위해 시설이 침범하지 않아야 할 공간을 뜻한다. 곡선에서는 추가 여유가 필요하다. [중부운수국 철도 용어](https://wwwtb.mlit.go.jp/chubu/tetsudou/yougo.html)

### 4.2 일본 사례를 반영하는 방식

도쿄도 교통국의 공개 자료에는 미타선 1,067mm, 아사쿠사선 1,435mm, 신주쿠선 1,372mm가 함께 존재한다. 따라서 일본 철도를 하나의 궤간으로 통일하거나, 궤간으로 지상/지하를 구분하면 안 된다. [도영 지하철 개요](https://www.kotsu.metro.tokyo.jp/about/service/subway.html)

게임용 규격 묶음 후보는 다음과 같다. 실제 노선 전체 사양의 복제나 첫 버전 지원 확정은 아니다.

- 일반 철제차륜·1,067mm·직류 1,500V·가공전차선 계열.
- 일반 철제차륜·1,435mm·직류 1,500V·가공전차선 계열.
- 일반 철제차륜·1,372mm·직류 1,500V·가공전차선 계열: 기존망 호환 사례.
- 제3궤조 도시철도 계열: 궤간·전압·차체 규격은 선택한 참고 모델별로 정의.
- 철제차륜 리니어 계열: 전용 추진 설비와 차량을 별도로 요구.

앞의 세 전철화 조합은 도영 노선 통계의 실제 사례를 참고한다. 차량 크기·신호까지 같다는 뜻은 아니다. [도쿄도 교통국 2020년도 통계 — 규격 사례](https://www.kotsu.metro.tokyo.jp/about/information/statistics/pdf/statistics_2020_03.pdf)

오에도선은 자기부상식이 아니라 차륜식 리니어이며, 차량과 선로 사이의 반응판을 이용한다. 이처럼 궤간·전압만 맞아도 추진 설비가 다르면 자력 운행이 불가능할 수 있다. [도쿄도 교통국 2023 사업 개요](https://www.kotsu.metro.tokyo.jp/about/service/pdf/kotsu_aramashi_2023.pdf)

### 4.3 호환성 판정 제안

검사 결과는 `가능`, `조건부 가능`, `불가능`, `자료 부족`을 구분한다. 자료 부족을 가능으로 처리하지 않는다.

- **기본 불일치:** 궤간·주행 방식·집전·전압·필수 신호 등이 맞지 않으면 영업 투입 불가.
- **공간·하중:** 직선뿐 아니라 곡선과 분기기에서도 통과 공간과 하중 조건 확인.
- **성능 조건:** 허용 속도·경사에서 견인·제동 성능이 충족되는지 확인. 감속으로 해결되지 않는 조건은 불가.
- **시설 조건:** 승강장, 회차 경로, 기지 접근·정비 능력은 후속 명세의 검사를 연결.
- **운영 조건:** 다른 회사 시설은 기술 적합성과 별개로 사용 계약·운행 승인을 확인.
- **다중 대응 차량:** 지원 규격 목록과 전환 조건이 명시된 경우만 허용. 자동으로 모든 전원을 지원하지 않음.
- **이동 목적:** 영업 자력 운행, 시험, 견인 회송은 구분. 견인도 공간·하중·연결기·견인차·경로 검사가 필요.

실제로 오에도선 차량은 아사쿠사선에서 자력 운행하지 못하지만 전기기관차로 견인하여 검사 시설로 이동한다. 이를 근거로 ‘자력 운행 불가’와 ‘어떤 방식으로도 이동 불가’를 분리한다. 견인 기능의 첫 버전 포함 여부는 미정이다. [도쿄도 교통국 보수점검](https://www.kotsu.metro.tokyo.jp/initiatives/safety/measures_safety/subway/maintenance/)

## 5. 구조 형식: 철도를 어디에 놓는가

비용·공기 산출의 후속 조사안: [구조 형식별 물량·비용·공기 계산](railway-structure-estimation.md). 초기 km당 패키지와 상세 물량식을 중복 적용하지 않는다.

다음은 구조 선택이 게임에서 발생시킬 입력·비용·운영 조건의 제안이다.

| 구조 | 추가로 필요한 정보 | 게임에 반영할 주요 부담 |
|---|---|---|
| 지표면 지상 | 용지 폭, 도로·건물 교차 | 용지, 방호, 단절, 소음, 교차 처리 |
| 성토 | 높이, 사면·옹벽, 지반 | 토공량, 넓어지는 점유 범위, 침하 대응 |
| 절토 | 깊이, 사면·옹벽, 지하수 | 굴착·반출, 배수, 주변 지반 대응 |
| 고가 | 높이, 경간, 교각·기초 위치 | 기초·상부 구조, 교각 충돌, 진동·경관 |
| 교량 | 하천·계곡 등 횡단 조건, 경간, 여유 높이 | 특수 구조, 기초, 작업 접근·환경 조건 |
| 지하 | 깊이, 지질·지하수, 기존 지하 시설 | 굴착, 방수·배수, 환기·피난 관련 요구 |

고가와 교량은 구조물을 공유하는 분류다. 한 구간을 양쪽에 중복 계상하지 않는다. 구조의 세부 유형과 횡단 조건으로 구분한다.

- 지하라고 반드시 특정 공법을 쓰는 것은 아니다. 구조는 완성 형태, 공법은 만드는 방법이며 3번 명세에서 다룬다.
- ‘지상은 항상 최저가, 지하는 항상 최고가’ 같은 고정 규칙 대신 용지·장애물·구조 물량으로 비교한다.
- 깊이를 늘려도 모든 충돌이 사라지는 것은 아니다. 역 접근·피난·환기·기지 연결 요구도 함께 변한다.
- 지상에서 지하, 고가에서 지상으로 이어지는 구간도 실제 길이를 가진 시설이다. 높이가 순간적으로 바뀌지 않는다.
- 도로 평면교차 허용 여부는 해당 규칙 프로필과 시나리오에서 검사한다. 새 철도를 그렸다는 이유로 자동 허용하지 않는다.
- 도로 입체교차는 고정된 도로 위·아래로 철도가 통과하도록 설계한다. 도로 이설 기능을 암묵적으로 추가하지 않는다.

## 6. 선형: 곡선과 경사가 비용·속도를 바꾼다

### 평면 선형

- 직선, 원곡선, 완화 구간을 표현할 수 있는 길이·곡률 정보를 받는다.
- 곡선 반경이 작아지면 차량별 통과 가능성·허용 속도·공간 여유를 다시 검사한다.
- 보기 좋은 지도 곡선과 열차가 실제 주행할 곡선은 구분한다. 화면 표현만 부드럽게 해도 판정은 달라지지 않는다.

### 종단 선형

- 높이는 기준고도를 명시한 레일 높이로 관리하고, 지표 높이와의 차이는 별도로 계산한다.
- 경사는 퍼밀(‰), 거리는 m, 곡선 반경은 m로 입출력 단위를 고정한다.
- 수평거리 1,000m에서 25m를 오르면 25‰다. **이 값은 단위 설명이지 일본 공통 허용 경사가 아니다.**
- 예를 들어 20m 높이 차를 25‰ 일정 경사로 연결하면 수평거리만 800m가 필요하다. 실제 설계에는 양 끝의 종곡선 등 추가 조건이 붙는다.
- 기울기가 바뀌는 지점도 즉시 꺾지 않는다. 종곡선 조건과 차량 통과 가능성을 검사한다.

### 속도 계산의 경계

게임의 구간 속도 상한은 시설·차량·곡선·분기기·신호·임시 제한 중 적용 가능한 최솟값으로 정한다. 실제 주행 속도는 여기에 가속·제동·경사·앞 열차·정차 위치를 반영한다. 제한 구간에 진입한 뒤 순간 감속하는 방식은 허용하지 않는다.

세부 수식·안전 여유·허용 반경·경사 수치는 후속 차량 모델 및 기준 프로필과 함께 검증한다. 현재는 임의의 숫자로 확정하지 않는다.

## 7. 선로 구성: 열차가 어디서 기다리고 추월하는가

| 구성 | 제공하는 선택 | 반드시 계산할 제약 |
|---|---|---|
| 단선 | 한 선로를 양방향 열차가 시간 분할 사용 | 방향 충돌, 교행 가능 위치, 지연 전파 |
| 복선 | 통상 방향별 선로를 분리 | 합류·역·회차 병목. 양방향 운전 가능 여부는 별도 설비 조건 |
| 복복선 | 완행/급행 또는 계통별 분리 등 | 배선·승강장·분기기 연결에 따른 실제 활용도 |
| 교행·대피선 | 반대 열차와 교행하거나 뒤 열차를 먼저 보냄 | 유효 길이, 연결 분기기, 진출입 시간 |
| 건넘선 | 인접 선로 사이 이동 | 허용 방향, 분기 속도, 다른 진로와의 충돌 |
| 분기·합류 | 지선 연결·계통 공유 | 평면교차 진로 충돌, 합류 처리 능력 |
| 입체 분기 | 높이를 달리해 교차 진로 분리 | 접근 경사·길이, 구조 공사, 남아 있는 합류 병목 |
| 회차 경로 | 종착 후 반대 방향 운행 | 사용 가능한 선로 연결, 차량 운전 방향, 점유 시간 |

- 단선 전체를 항상 열차 한 대로 제한하지 않는다. 초기 운행 모델도 교행 지점·폐색·진로 충돌 범위를 구분해야 한다.
- 복선은 열차가 무조건 반대 방향 선로로 피할 수 있다는 뜻이 아니다. 연결 설비와 운전 조건이 있어야 한다.
- 급행을 설정해도 앞 열차를 통과하지 않는다. 별도 경로와 시간 여유가 없으면 따라간다.
- 복복선이라고 수송력이 자동으로 네 배가 되지 않는다. 역·합류·회차·차량·전력 중 가장 좁은 부분이 제약한다.
- 교행·대피선의 유효 길이가 편성보다 짧으면 정상적인 대피 경로로 사용할 수 없다.
- 종착역마다 별도 회차선을 강제하지는 않는다. 승강장 선로와 건넘선으로 가능한 배선도 허용하되, 실제 점유 시간과 충돌을 계산한다.
- 지도에서 두 선이 겹쳐 보인다는 이유로 연결하지 않는다. 같은 높이인지, 물리적 분기 연결이 있는지 확인한다.

## 8. 궤도·전력·신호: 보이지 않아도 필요한 설비

### 궤도

기본 선택은 자갈도상과 슬래브·직결 계열로 묶고, 레일·침목·체결·방진의 상세 등급은 고급 설정으로 확장하는 안을 제안한다. 슬래브와 직결의 세부 구조를 동일한 제품으로 취급하지 않는다.

JRTT는 고가·교량·터널·토공 구간의 슬래브 궤도 적용과 여러 궤도 구조를 소개한다. 구조 위치만으로 도상 종류를 고정하지 않는 근거다. [JRTT 궤도 기술](https://www.jrtt.go.jp/construction/technology/track.html)

게임에서는 초기 공사 물량, 정기 보수 작업량, 보수 시 운휴, 갱신 작업, 소음·진동을 비교한다. 슬래브를 유지관리 불필요 시설로 만들지 않는다. 단가와 보수 주기는 아직 미정이다.

### 전력

급전 방식의 호환과 공급 능력은 별도다. 차량이 전압에 대응해도 공급 용량이 부족하면 계획한 동시 운행을 충족하지 못할 수 있다. 변전·급전 구간, 설치 상태, 가용 용량과 공급 중단을 표현할 인터페이스가 필요하다. 상세 전력망 계산의 깊이는 추후 결정한다.

### 신호·보안

ATS·ATC·ATO 같은 명칭 하나로 호환성을 판단하지 않는다. 차상·지상 장비의 구체적인 시스템 식별자와 버전을 관리한다. 자동 운전 기능과 열차 간 안전 간격 보장은 분리한다.

운행 엔진은 점유·진로 예약·충돌을 처리해야 한다. 빠른 배속에서도 두 열차가 같은 충돌 구간을 동시에 통과하지 않게 한다. 신호 등급을 올리면 모든 병목이 일정 비율로 해소된다는 계산은 사용하지 않는다.

## 9. 시설·운행 서비스·소유권 분리

다음은 지도 표현에 의존하지 않는 시스템 모델 제안이다.

- `StructureAsset`: 터널·고가·교량 등 공유 토목 구조와 소유자, 수용 공간.
- `TrackSegment`: 개별 선로, 길이·높이·곡률·기술 규격·구조물 참조·사용 상태.
- `Junction`: 물리적 연결과 허용 진로·서로 충돌하는 진로.
- `TechnicalProfile`: 궤간·전력·한계·하중·호환 규격의 버전 있는 묶음.
- `ServicePattern`: 사용하는 물리 경로, 정차역, 운행 회사. 상세 시간표는 후속 명세.
- `AccessAgreement`: 타사 시설 사용 범위·기간·대가·운행 조건. 기술 호환성과 별도 검사.
- `InfrastructureRevision`: 설계안과 현재 사용 중 시설 버전의 구분.

같은 선로 위에서 완행·급행 또는 다른 회사의 열차가 운행해도 선로 자산과 공사비는 한 번만 생성된다. 운행 서비스를 삭제했다고 선로를 철거하거나 토목비를 환급하지 않는다.

궤도·급전·신호 등의 준비 상태는 분리한다. 단일 ‘건설 완료’ 플래그로 모든 장비가 생기지 않는다.

## 10. 비용·공사기간·개량과의 연결

### 물량과 회계 경계

- 노선 길이, 구조물 길이, 개별 선로 길이를 구분한다.
- 동일 길이 10km의 복선 예시: 단순화하면 경로 10km, 선로 연장 합계 20km다. 레일 두 줄을 이유로 선로 연장을 다시 두 배로 하지 않는다.
- 복선 터널은 단선 터널 두 개일 수도, 두 선로를 수용하는 하나일 수도 있다. 구조물 물량은 실제 선택에 따른다.
- 공사 견적은 용지·조사설계·토목·궤도·전력·신호·환경 대책·시험 등의 항목을 분리한다.
- 공유 구조물은 구조물 ID로 한 번만 계상하고, 선로·설비는 실제 물량을 계상한다.
- 역·기지·차량·금융비용의 포함 여부를 명시한다. 견적과 실제 지급, 장부 자산 가액을 같은 숫자로 취급하지 않는다.

### 기간과 운행 준비

이 문서는 작업에 넘길 구조·길이·개수·호환 조건을 정의한다. 공기는 3번 공법 명세에서 물량·생산성·자원·선행 작업으로 계산한다. ‘지하 1km는 무조건 N개월’ 같은 단일 확정식을 두지 않는다.

선로 완공 후에도 관련 설비·역·차량·기지 접근·인력·시험·승인이 준비되어야 개통한다. 부분 개통은 그 구간만으로 조건을 충족할 때 허용한다.

### 개량과 철거

- 단선→복선: 추가 용지·구조 수용력·선로·신호·연결 공사가 필요한 프로젝트.
- 지상→지하: 대체 시설 건설, 접속 전환, 기존 시설 처리의 단계별 프로젝트.
- 궤간·전력 변경: 차량·분기기·기지·기존 운행에 대한 영향 분석이 필요한 변경.
- 공사 중 설계 변경: 견적·기간·계약 변경과 기존 작업 활용 가능성을 다시 계산.
- 철거: 운행 및 차량 점유·후속 경로를 검사하고, 중단·우회 계획과 철거 비용·기간을 처리.

운행 중 선로를 클릭 한 번으로 다른 규격으로 바꾸거나, 공사 중인 선로로 열차를 즉시 옮기지 않는다.

## 11. 지도 담당과 시스템 담당의 경계

지도 담당은 후보 선형·높이·지형·장애물·토지 조건 등의 공간 입력을 제공한다. 시스템 담당은 그 입력을 사용해 규칙 위반, 기술 호환성, 물량, 운행 제약을 반환한다. 이 문서는 지도 편집기 구현을 변경하지 않는다.

입력에는 단위·좌표/고도 기준·자료 버전·정확도·조사 상태를 포함한다. 미조사 지질·권리관계·지하 시설이 알려진 것처럼 취급되지 않게 한다.

판정은 문제 코드, 해당 구간/시설 ID, 심각도, 원인, 해결 후보를 반환한다. 예: `GAUGE_MISMATCH`, `CLEARANCE_UNKNOWN`, `GRADE_EXCEEDED`, `NO_TURNBACK_PATH`, `POWER_NOT_READY`.

‘자료 부족’은 설계안 저장을 막을 필요는 없지만, 필요한 조사 없이 확정 견적이나 개통 승인을 내주지는 않는다. 사용자가 볼 예상 비용·기간에는 추정 범위와 불확실성 원인을 표시한다.

저장 데이터에는 사용 중 시설과 설계안 버전, 소유자, 연결 관계, 규격 버전, 설비 상태, 작업 참조와 운행 중 점유·예약 상태가 포함되어야 한다. 상세 저장 형식과 이전 버전 변환은 구현 전에 별도 확정한다.

## 12. 검증 시나리오

1. 궤간이 다른 차량을 배정하면 구간과 원인을 표시하고 영업 투입을 거절한다.
2. 궤간이 같아도 전압·집전·신호·한계가 다르면 각각 판정한다.
3. 전력·신호의 필수 자료가 없으면 ‘호환 가능’으로 표시하지 않는다.
4. 리니어 추진 차량은 반응판 없는 경로에서 자력 운행할 수 없다. 견인은 별도로 검사한다.
5. 지상→고가→지하로 이어지는 같은 규격의 경로는 연결·선형 조건 충족 시 허용한다.
6. 높이가 다른 두 선의 지도상 교차로 연결 노드를 생성하지 않는다.
7. 짧은 거리에서 큰 높이 변화를 만들면 경사·종곡선 조건 위반을 반환한다.
8. 단선의 반대 방향 열차는 충돌 진로에 함께 진입하지 않고 교행 지점을 사용한다.
9. 대피 경로가 없으면 급행이 앞 열차를 추월하지 않는다.
10. 대피선 유효 길이가 부족한 편성은 그 선로에 대피 배정하지 않는다.
11. 복선이 있어도 실제 회차 경로가 없으면 왕복 운행 계획을 유효하다고 판정하지 않는다.
12. 완행·급행 서비스를 같은 시설에 추가해도 건설 자산·공사비를 중복 생성하지 않는다.
13. 타사 시설에 기술적으로 들어갈 수 있어도 사용 권한이 없으면 영업 운행을 거절한다.
14. 선로가 완성되어도 급전·신호·차량·기지 등이 미준비면 개통 불가 사유를 반환한다.
15. 설계안의 복선화를 저장해도 사용 중인 단선 상태는 공사·전환 완료 전까지 유지된다.
16. 같은 초기 상태·명령·시드의 배속 및 저장/복원 비교에서 중복 준공·지급·충돌이 발생하지 않는다.

## 13. 이번 초안에서 아직 결정하지 않은 것

- 첫 구현에 포함할 주행 시스템, 궤간·급전 조합과 차량군.
- 곡선·경사·한계·하중의 실제 참고 규격 및 게임 조정값.
- 공사 단가·생산성은 [2026년 초기 기준표](railway-system-baseline-2026.md)에 v0.1 가정값을 두었다. 실제 자료 보정, 유지관리 비용·주기, 설비 고장 모델은 미확정.
- 신호·전력 계산의 깊이와 최대 시뮬레이션 규모.
- 기본 자동 배선이 제공할 범위와 고급 편집 옵션.
- 자유 샌드박스에서 시간·비용·호환성 제한을 각각 해제할 수 있는지.

**이번 1번의 산출물은 선택 항목과 시스템 규칙의 상세 초안이다. 코드 구현 완료나 모든 철도 종류의 지원 확정을 뜻하지 않는다.** 2번의 첫 상세안은 [승강장·선로 배치와 주행 시스템 호환성](railway-station-platform-spec.md)에 이어서 정리한다.
