# B14-4 철도 대체버스 운행·경영 엔진

작성일: 2026-10-05

## 구현 범위

철도 장애의 부분운휴 명령이 발령된 뒤, 운휴 경계역을 잇는 대체버스를 조달하고 실제 승객 경로에
투입한다. 공간 후보는 M8 지도 계약이 공급하고, 이 모듈은 도로 사실을 다시 계산하지 않는다.

운행 계약은 `transitline.rail-replacement-operation/1`이다. 장애 이벤트, 관제명령, 지도 후보와
revision, 가상 노선 ID, 정류 역, 구간별 도로거리, 버스 종류·조달방식·차량 수, 동원·운영비,
운행실적과 정산 누계를 보존한다.

## 버스와 조달 방식

아래 값은 실제 시장가격을 주장하는 자료가 아니라 2026 JPY 게임 밸런싱 기준이다.

| 차량 | 정원 | 차폭 | 평균 운행속도 |
| --- | ---: | ---: | ---: |
| 미니버스 | 25명 | 2.1 m | 7.0 m/s |
| 일반 노선버스 | 70명 | 2.5 m | 7.5 m/s |
| 전세 코치 | 55명 | 2.5 m | 8.3 m/s |

| 조달 | 동원시간 | 차량당 동원비 | 차량·시간당 운영비 | 평판 |
| --- | ---: | ---: | ---: | ---: |
| 긴급 전세 | 60분 | ¥180,000 | ¥18,000 | 0 |
| 사업자 상호지원 | 120분 | ¥100,000 | ¥15,000 | +1 |
| 지자체 긴급요청 | 180분 | ¥60,000 | ¥12,000 | -1 |

차량 수와 왕복시간으로 방향별 배차간격과 시간당 수송력을 계산한다. 동원비는 시작 즉시 지급하고,
운영비는 실제 활성 차량분을 누적해 `settleOperatingDays()` 또는
`settleRailReplacementOperations()`에서 원장에 게시한다.

## 공간 사실의 안전 처리

- `roadConnection: false`: 운행 불가.
- `roadConnection: null`: 안전하다고 가정하지 않고 조건부.
- 도로 최소폭이 버스 차폭보다 작음: 운행 불가.
- 도로 폭 `null`: 조건부.
- 두 미상값은 `confirmUnknownRoadFacts: true`를 명시해야만 실행되며 `assumptions[]`에 남는다.
- 각 정류 역 사이의 측정 도로거리가 없으면 직선거리로 대신하지 않고 거절한다.
- 지도 역 ID는 운영 노선의 `sourceStationId`를 통해 정확히 하나의 운영 역으로 연결돼야 한다.

M8 계약이 확정되어 `replacementGeometry`와 선택한 `routeId`를 직접 받을 수 있다. 시작 요청에는
선택 당시의 `replacementGeometryRevision`을 반드시 함께 보내야 하며, M7 관제명령의 geometry ID/revision,
부분운휴 후보, 회차 후보, 운영 선로 매핑과 모두 일치해야 한다. 하나라도 오래됐으면 운행을 만들지 않는다.

```js
{
  eventId,
  controlOrderId,
  replacementGeometry,          // transitline.rail-replacement-transport-geometry/1
  replacementGeometryRevision,  // 플레이어가 선택한 당시 revision
  routeId,
  vehicleClassId,
  procurementStrategyId,
  vehicleCount,
  confirmUnknownRoadFacts?,
  confirmSpatialConstraints?
}
```

어댑터는 `stationSequence`를 운영 역으로 연결하고, 경로의 역별 `alongMeters` 차이로 각 구간의 실제
경로 길이를 만든다. 도로 이탈, 양 끝 도로 미접속, 경계역 미도달, 역 순서 불일치는 확정 실패다.
도로·정류장 접속 미상과 폭 미상은 명시적 확인 없이는 조건부이며, 경로 주변에 교량·터널·중량·높이
제약이 있으면 별도의 `confirmSpatialConstraints`가 필요하다. 직선거리를 도로거리로 대신하지 않는다.

## 실제 시뮬레이션 연결

- 활성 대체버스는 음수 가상 노선 ID를 받는다.
- 기존 Dijkstra 경로와 pop 기반 시간표 라우터 양쪽에 대체버스 패턴이 들어간다.
- 중간 운휴로 철도 노선이 양쪽으로 갈라져도 `철도 → 대체버스 → 철도` 경로가 만들어진다.
- 버스 차량은 동원 완료 뒤 배차되고 정원만큼 승객을 태운다.
- 승객은 대체버스 종점에서 철도로 환승하거나 목적지에 도착한다.
- 대체버스로 최종 도착한 승객 수입은 원래 장애 철도 운행노선에 귀속된다.
- 장애·관제명령 종료 시 새 승객 경로에서 즉시 빠지고, 운행 중 버스는 승객을 내려준 뒤 종료한다.

## 저장과 원자성

운영, 차량 trip, 가상 노선 ID 시퀀스, 비용 누계는 통합 운영 스냅샷에 저장된다. JSON이
`-Infinity`를 `null`로 바꾸는 배차 초기값은 복원 시 다시 `-Infinity`로 되돌린다.

동원비·평판과 운영 상태는 하나의 런타임 작업으로 처리한다. 현금이 부족하면 원장과 운영 상태를
모두 이전 스냅샷으로 복구한다. 운영비 정산도 경영 트랜잭션과 운영 스냅샷 복구 경계 안에서 실행한다.
